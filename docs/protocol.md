# 在场服务器

这个进程只同步玩家外观和移动。它不保存玩家档案，也不转发战斗。

## 启动

在独立仓库 `HaqiGameServerLite` 根目录执行：

```
npm run presence
```

默认只监听 `127.0.0.1`。网关是 `http://127.0.0.1:8797`，管理页是 `http://127.0.0.1:8797/admin`。网关进程自己拉起第一台世界服，WebSocket 在另一个端口，默认 `ws://127.0.0.1:8798`。管理页的「增加本机世界服」会在同一进程里再开一台，使用下一个空闲端口。游戏服使用 Node 自带的 WebSocket 文本帧。VS Code 任务名是 `haqi server: start`。

可用环境变量：`PRESENCE_HOST`、`PRESENCE_GATEWAY_PORT`、`PRESENCE_GAME_PORT`、`PRESENCE_MACHINE_ID`、`PRESENCE_ADMIN_TOKEN`。设置管理口令后，暂停、拆分、合并和清空需要请求头 `x-admin-token`。

程序化调用 `startGameServer({gatewayUrl, host, port, machineId})` 可注册额外世界服。目前没有单独的远端世界服 CLI；远端部署还需配置可达的 WebSocket 地址和控制面保护。

## 结构

- 网关记录哪台机器上有哪些实例，并决定玩家进入哪一个。它不转发坐标。
- 游戏服没有持久状态。断线或重启后，客户端重新 hello，并带上自己的外观和坐标。超过 15 秒没有心跳的机器不再接收新玩家。
- 一个实例最多 500 人。一台游戏服进程最多 8000 人。到 400 人时，网关在同一台机器上打开新实例，并按地图区域整组搬走，同一格子里的人留在一起。人满后新玩家改派到其他游戏服。
- 两个实例各自不超过 100 人、加起来不超过 380 人时，可以合并。自动拆分或合并每台机器至少间隔 10 分钟，并提前 8 秒用中文通知。管理页可以手动执行同样的操作。
- 房间名由客户端给出，不必事先登记。一名玩家同时只在一个房间里。只有一个人时不建立房间对象；第二个人进入才建立，彼此才能看见。人走光后房间立刻删除，只剩一人时也立刻收回对象。

## 移动

客户端最多每秒发送一次 `move`。更早的移动会被丢掉。接收方用最近两个样本做插值。服务器按距离决定转发间隔：

- 800 单位以内：每秒一次
- 800 到 2000 单位：每 4 秒一次
- 更远：每 8 秒一次

单次位移超过 `maxSpeed`（默认每秒 2500）会被钳制。`teleport: true` 用于门和换岛，仍限制在地图边界内。30 秒没有任何消息会断开。

人不多时，挤在一起的房间每秒只编码一帧。一个房间超过 64 名其他玩家时，每秒优先同步最近的人，其余的人轮流出现，避免一帧大到拖住进程。人散开时，只查找附近的格子。慢连接上写不出去的移动帧会丢掉，控制消息仍然发送。单条客户端消息不超过 16 KB，一台游戏服最多接受 8000 条连接。

## 客户端顺序

1. `POST /api/join`，正文包含 `playerId`、`roomId`、`x`、`y`。
2. 连接返回的 WebSocket，发送 `hello`，带上 `instanceId`、名字、外观、房间和坐标。
3. 用 `move`、`enterRoom`、`leaveRoom`、`appear` 更新。`appear` 是不超过 2 KB 的 JSON 对象。

服务器会发送 `welcome`、`roster`、`relay`、`joined`、`left`、`notice` 和 `migrate`。同机迁移不更换这条 WebSocket。
