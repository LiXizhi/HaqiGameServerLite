# 用户日报

`npm start` 默认启用本机用户分析，管理页 `/admin` 的“用户日报”选择日期查看；留空查看今日采样数据。输入 `PRESENCE_ADMIN_TOKEN` 对应口令，未配置口令时日报接口拒绝访问。北京时间每天零点后的首个分钟采样自动生成前一天 JSON 日报，服务重启时补生成已保存的历史日报。无需外部分析服务、数据库或前端库。

## 口径

- 只统计通过鉴权且世界服实际发送 `welcome` 的账号；网关分配、鉴权失败、拒绝入场、健康检查均不计。一个项目内多角色、多连接去重；跨项目分别计数。目前管理页显示所有本机项目合计，不是跨项目自然人数。
- 活跃账号：当日成功入场或当日在线采样中出现的账号。短连接也记录，跨午夜事件按原始时间归属日期。
- 首次观测：从启用分析以来第一次出现，不等于账号注册时间。上线初期已有用户也会列入首次观测群组。
- 在线曲线每分钟一点，峰值和均值基于实际采样；不代表秒级真实峰值，也不计算精确在线时长。缺失分钟为 `null`，零在线为 `0`。
- 次日／7 日留存：报告日前 1／7 天首次观测群组中，在报告日活跃的比例，同时显示分子、分母；不是累计七日回访率。没有群组或历史数据时显示暂无基数。
- 日报与前一天、上周同日比较活跃账号变化率；JSON 同时包含比较日的完整基本指标。基数为零时不输出无穷增长。今日实时数据与整日比较仅供参考。
- 全日采样覆盖率、被丢弃入场记录数随报告展示。停服、故障、未启用分析的时段不补零，数据不完整时留存与活跃可能低估；历史无法追溯。

## 性能、存储与边界

主线程仅在成功入场／断开维护内存 Map，每分钟传递一次快照；不监听移动包、不在游戏请求中读写磁盘。散列、去重、历史汇总和原子文件替换在单独 Worker 执行。最多一个批次在途；Worker 忙时跳过采样，待处理入场记录上限 20,000，超出有丢弃计数。故障不会阻塞游戏，控制台记录分析不可用，需要修复目录并重启服务恢复。不能承诺完全零开销，仍有内存维护、每分钟快照复制及 Worker CPU／磁盘成本。

默认目录 `var/analytics`（已忽略 git），`PRESENCE_ANALYTICS_DIR` 可覆盖；设置 `PRESENCE_ANALYTICS=0` 禁用。只允许一个主服务进程写一个目录，多个部署须配置各自目录；当前不汇总远程独立世界服。通过程序调用 `startPresence` 时需显式传入 `createAnalytics(...)` 实例；CLI 会自动创建并注入本机新增世界服。

`state.json` 保存随机盐、HMAC 账号标识、首次观测日期及最近 91 个自然日的去重集合与分钟数据。首次观测索引长期保留，随累计账号数量增长；已生成的日报 JSON 长期保留。目录需持久卷并纳入备份，不能放在静态公开目录。用户名只在短期内存中使用，不落盘，不采集 token、IP、位置或移动轨迹。删除目录会重置首次观测历史。

正常关闭尽量等待刷新（每阶段最多 2 秒）；崩溃可能丢失上次落盘后的入场记录。文件损坏不会自动清空历史，需要人工恢复备份。Worker 写入失败后不自动重试，以免隐藏长期故障。

接口：`GET /api/admin/report?date=YYYY-MM-DD`（或 `today`），请求头 `x-admin-token`。只读取预计算 JSON，不在 HTTP 请求里扫描历史。日期不存在返回 404；日报不含账号标识。
